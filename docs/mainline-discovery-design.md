# 主线板块识别与潜力个股观察：功能设计

状态：总体设计与分阶段路线。现已实现事件题材、TDX行业分类全成员观察、行业指数扫描、妙想受控补充、盘中时间确认和方向独立验证。真实取数、HTTP链路与自动测试范围见[功能说明](mainline-feature.md)。行业指数持续性不等于逐日成分中位数趋势，妙想空关系表不作为自动拓展依据；本页其余统计和研究提案不能视为已交付。

2026-11-06 二次核查修订：补查产业资讯、产业信号、产业研究、候选池、盘中快照、明日验证、事件日历及提醒。采用“共享计算结果、嵌入已有页面”的方式；细项和实现优先级见第 13 节。第 13 节保留方案复核结论；随后首版实现及验收以[功能说明](mainline-feature.md)为准。

## 1. 可行性与功能目标

可以增加。项目已有情绪复盘、每日复盘、题材事件树、题材轮动、盘中情绪、昨日梯队、批量行情和候选池。新增功能的重点是把这些数据按同一个观察时点组织起来，形成可复核的判断链：

**市场环境 → 活跃行业/事件题材 → 持续性与扩散 → 关联个股 → 条件核对 → 后续事实验证。**

用户可以回答四个问题：

1. 当前市场有哪些持续活跃、正在扩散或开始减弱的方向？
2. 今天的活跃方向与昨日复盘是否一致，变化发生在哪些读数上？
3. 哪些个股已经表现出与这些方向一致的成交、相对强弱或经营关联特征？
4. 哪些结论有完整证据，哪些只是样本观察，哪些因为数据不足暂不能判断？

“主线”定义为在指定样本和时间窗口内，多项市场表现持续一致的分析标签，不是客观唯一答案。“潜力个股”在产品中落为“关联观察股”：依据已发生事实和可复核关联纳入观察，不能表示未来上涨概率、收益预测或买卖优先级。

允许多个方向并存，也允许输出“未形成明确主线”。不强制每日选出一个板块或固定数量的股票。板块表现与个股表现分别核对，不能因为归属强势方向就自动通过个股条件。

| 盘中快照与验证 | `shortline/intraday.ts`、`verification.ts` | 交易日门禁、六时点调度、市场读数对账 | 方向级成员快照、独立验证记录，保持原验证契约 |
| 日历与提醒 | `events.ts`、`schedule.ts` | 公开事件解析、任务门禁、去重消息 | 公开观察范围、方向变化摘要及预算控制 |
| 妙想补充源 | `.agents/skills/mx-data/`、`.agents/skills/mx-search/` | 结构化数据查询、事件检索脚本 | 注册端点、响应适配、日期/单位校验、真实联网验收 |

重要实现限制：现有题材树会截取展示题材，单题材成员也只展示前 8 只；不能把显示名单当作全量样本。题材轮动也有展示范围限制。新聚合器必须获取完整计算输入，或增加保持旧契约的全量输出；拿不到全量时明确标为展示样本，不能重建“全市场主线榜”。

现有候选池明确按用户条件核对、按代码排序，不做个股综合评分。新功能沿用这个行为，新增观察范围和证据，不改变原候选池语义。

## 3. 页面与使用流程

首版在“每日复盘”增加“主线方向”区域或分页，在“盯盘”页提供同一结果的简版入口；详细条件核对进入现有“候选池”。先不增加侧栏栏目。使用频率和信息量证明有必要后，再考虑独立“主线与观察股”页面；各入口始终读取同一快照。

### 3.1 页面结构

1. **数据状态栏**：业务日、模式、观察截止时间、各源实际行情时间、完整/部分结果、上次成功版本、缺口。旧结果显示原时间与“已过期”，不展示为当前结果。
2. **市场环境卡**：情绪水平、较昨日变化、指数趋势、成交额，以及各项样本数。沿用情绪历史展示的分位含义，不能把分位解释为胜率。
3. **方向卡片**：行业与事件题材分开展示；包含持续活跃、扩散观察、单日活跃、分歧、减弱、数据不足等状态及逐条依据。
4. **关联观察表**：代码、名称、关联依据、角色标签、条件三态、实际指标、样本范围、证据时间、缺失原因，默认按代码排序。
5. **证据与历史**：查看原始来源、算法版本、参数、上一次状态、状态改变原因，支持导出本机报告。

方向展示可按当天涨停数量、成分上涨占比等明确指标排序，必须注明指标和口径；不提供含义不明的“AI 潜力分”。个股角色仅描述事实，例如“昨日涨停样本”“成交活跃样本”“关联待核验”。

### 3.2 两种模式

| 模式 | 输入与含义 | 输出 |
|---|---|---|
| 收盘复盘 | 所选业务日及之前、在对应记录时点已知的数据 | 当日方向状态、完整条件核对、与上一交易日比较 |
| 盘中观察 | 前一交易日复盘基线 + 今日截至观察时刻的数据 | 对昨日方向的延续/减弱、新方向观察、发生变化的事实 |

盘中不以未完成日成交额直接除以前一日全天成交额来判断放量。需要同一时刻历史累计成交额，或明确使用已完成分钟区间；相应历史数据不存在就返回缺数据。

截图中的情绪历史可直接作为环境卡的依据。例如截图显示涨停家数、晋级率下降，而最高连板上升：可以描述为“短线反馈减弱，高度与广度分化”。这张图本身没有题材分布，不能据此识别具体主线。截图只用于界面设计举例，正式报告仍读取服务数据和证据，不把图片数字当作本次取数结果。

## 4. 行业与事件题材的关系

建立独立的 `direction_id`，包含类型、源命名空间和源标识。行业分类、概念成分、涨停原因题材不直接合并。

- **行业**：使用明确分类体系与成分日期；可以计算完整成分的涨跌宽度和成交额。
- **概念板块**：使用源站概念成员，名称相同也不保证不同源成分相同。
- **事件题材**：源于涨停原因或公开事件，通常只覆盖事件样本，不能当作完整行业成分。
- **经营关联**：公司公告或可追溯主营数据支持的关联，记录有效日期和证据强弱；新闻提及不能自动等同核心业务。

题材同义词采用人工可审查、版本化映射。保留原标签与映射理由，不让模型自行把不同产业链环节合并。一股多题材允许分别出现，但同题材内部按证券标识去重；不同题材数量不能直接相加当作全市场数量。

成员关系至少包含证券代码及市场、方向标识、关系类型、来源、原始引用、业务有效区间、首次获知时间和版本。未知起始时间不能倒填到历史。北交所及不同涨跌幅制度分别标明覆盖范围，不把同花顺未收录的北交所题材记作零。

## 5. 主线识别规则 v1

第一版使用解释清楚的条件组合，不先训练黑箱模型。以下是供实施和历史回放检验的初始规则，不代表经验上已证明有效；所有参数随结果保存。

### 5.1 数据门槛

- 先判断交易日与交易时段；未来日期拒绝，非交易日默认展示明确标日的最近收盘结果。
- 单日观察只要求当日有效池和有效题材关系；持续性判断另要求至少 3 个连续交易日的可比历史。历史不足不阻断单日观察。池内存在未知题材时，已观察数量可视为下限，不据此确认全市场领先、缺席或减弱。
- 分别记录涨停池完整性、题材归因覆盖率、方向成员行情覆盖率和时间有效率。方向内固定队列数据完整时，可生成“已覆盖样本持续活跃”；其他股票归因缺失不让这个方向的已知事实失效。确认目标市场整体领先、某方向完全消失或全量横向排名时，才要求比较范围与相关关系完整；否则禁用相应结论，并展示下限和未归因样本数。不把全部涨停股都有题材串当作所有功能统一的前置条件。
- 完整行业广度要求有明确成分分母。初始要求可用行情覆盖至少 90%、有效成员至少 10 只；小行业单列小样本，不与大行业直接比较。
- 分母为零、分母未知、成员缺失、时间过期分开处理。真实空池与请求失败分开保存；现有某些端点把空池视为不可用，实施时需由源适配器证明空池有效后才能参与零值计算。

严格门槛可能使早期经常出现“数据不足”，这是需要在验收中评估的数据服务问题，不能通过把缺失补零消除。

### 5.2 事件题材的事实指标

设 `U(d,t)` 为 d 日截止 t 的有效涨停集合，`B(d,t)` 为相同截止时间的有效炸板集合，`M(g,d,t)` 为当时已知的题材 g 关联集合。按代码去重：

| 指标 | 定义 | 边界 |
|---|---|---|
| 当日涨停数 L | `|U ∩ M|` | 关系缺失时只给下限 |
| 首板数 F | `U ∩ M` 中按端点连板数口径为 1 的数量 | 反包另标，不改写为连续板 |
| 延续率 C | 昨日收盘题材涨停成员中今日仍涨停数 / 昨日该样本数 | 分母为零时为 null，不能记为 0% |
| 炸板样本率 R | `|(B \ U) ∩ M| / |(B ∪ U) ∩ M|` | 集合先去重；须检查源池是否包含回封票，题材缺失影响分母时不出完整值 |
| 近 5 日活跃天数 A | 所观察 5 个交易日中 `L > 0` 的天数 | 缺日不得当零；不足 5 日写实际窗口 |
| 同题材昨日反馈 | 固定昨日成员的今日涨幅中位数、上涨占比 | 显示成功报价数 / 原始队列数，不仅统计继续涨停者 |
| 扩散变化 | 固定截点间新增首板、有效关联个股数量变化 | 区分价格变化与新获得关系数据造成的变化 |

新炸板样本率如与旧题材树公式不同，使用新字段名和算法版本，不静默改写既有读数。盘中池来自多个请求时记录最大时差，时差超出快照容差则不算跨池比率。

### 5.3 事件题材状态

状态拆为独立维度，分别计算三态结果，避免一个互斥标签遮住其他事实：

| 维度 | 初始规则 | 输出含义 |
|---|---|---|
| 当日活跃 | 今日 L≥3 | 已有多股事件表现；不要求历史完整 |
| 持续性 | 当日活跃、最近连续 3 个交易日 L>0、昨日题材样本≥3、C≥30% | 持续活跃，进入主线候选 |
| 扩散 | 当日活跃、F≥2、昨日 L>0 且今日 L 大于昨日 | 首板与数量扩散观察，可与持续性同时成立 |
| 分歧 | R≥50%，且完整尝试样本至少 4 只 | 分歧明显，可与持续活跃同时成立 |
| 未延续 | 昨日 L≥3、今日 L=0，且当日相关归因完整 | 昨日活跃、今日未再出现涨停样本 |

缺某维度输入只影响该维度。例如历史不足返回“当日活跃，持续性未知”，不能把它错误记为持续性不满足。所有用于判定的条件都有效且不满足时，才返回“一般观察”。多个题材可以同时是主线候选；没有满足项时返回空候选和原因。

主线卡可以同时显示“持续活跃 / 首板扩散 / 分歧明显 / 样本覆盖不足”，不把复杂市场压成唯一的好坏等级。“新出现”需有完整历史归因，否则只能称“本次首次观察到”。

盘中候选需要两次独立更新的有效快照支持，间隔至少 5 分钟，两次均满足条件才显示“盘中持续活跃”；缓存重放不计第二次。回落后保留状态历史，不能删除此前记录。收盘标签由收盘数据重算并形成新版本。

这里的“两次满足”指持续性必需条件有效且满足，不要求分歧条件为假。盘中 L 的变化必须标明同日截点，不能把上午数与昨日全天数直接解读为强弱变化。市场环境只提供解释背景；首版不按情绪临时改阈值，也不因市场偏冷就隐藏真实活跃方向。

### 5.4 行业方向

行业单独计算：成分上涨占比、成分涨幅中位数、相对同市场基准涨幅、成交额占可比样本比重、近 3 个交易日同口径变化。前收盘价缺失则不能计算相对涨幅；复权体系不一致不参与跨日比较。

v1“行业持续活跃”的初始规则：完整性达到门槛；今日成分上涨占比≥60%；今日成分涨幅中位数高于预先指定、同市场同时间基准；连续 3 个交易日相对强弱为正。基准和行业成分版本需明确。行业资金流只作独立辅助证据，不成为必需条件。

行业标签与题材标签各自保留。只有存在可追溯映射时才显示“行业与事件共同活跃”，不把概念热度自动归给整个行业。

## 6. 潜力个股观察的形成方式

### 6.1 两阶段构建范围

**第一阶段：事件样本观察。** 复用当前及前一交易日题材涨停、首板、炸板样本，列出与活跃方向相关的股票。这个版本可以较快实现，但只能发现已进入事件样本的股票，不能宣传为全市场挖掘未启动个股。

**第二阶段：方向成分拓展。** 获取可信概念/行业全成员及经营关联，再批量核对尚未进入涨停样本的公司。mx-data 可以作为结构化关系补充，必须保留原表、查询条件、返回时间、分页完整性和关系证据；返回自然语言摘要不能直接成为成员主表。

### 6.2 逐只条件核对

| 条件 | 处理方式 |
|---|---|
| 方向关联 | 有时点有效的关系证据；只有模糊新闻提及则“待核验” |
| 名称/交易状态 | ST、退市、停牌等单独核对；状态缺失不能视为通过；盘前零成交不推断停牌 |
| 流动性 | 使用用户设置的成交额/换手率范围；缺数据独立成组 |
| 相对强弱 | 同时点相对指定基准的已发生涨幅差，显示原值及算式 |
| 趋势条件 | 完成日线计算均线及近 N 日表现；未完成日线单列，不混入完成日均线 |
| 成交变化 | 收盘比较完整日，盘中比较相同已完成区间；不可比则缺数据 |
| 事件真实性 | 公告或可访问原始来源支持，区分媒体归因、研究观点和公司确认 |
| 风险事实 | 已知减持、监管、业绩、解禁等事件及时间；未检索到不等于没有风险 |

数值边界由用户确认的条件模板定义，默认模板以“研究示例”标识，不给出未经验证的最佳阈值。逐项返回 `met / unmet / missing`，复用候选池的三态逻辑。有不满足项则排除；没有不满足但有缺数据则进入待补全组；其余进入全部满足组。基础输入全缺失时不得显示“全部满足”。

### 6.3 个股卡片内容

展示“为何纳入、哪些条件满足、哪些不满足/缺失、有哪些相反事实、下一次需要核对什么”。例如“需要补齐同时间成交额后才能判断成交扩张”，属于验证任务，不生成突破买点、目标价、止损价或仓位指令。

一键加入自选需用户操作；自动生成观察结果本身不修改自选或持仓。个人持仓不作为外发研究范围，不发送成交、成本、数量、盈亏给模型或妙想服务。

## 7. 数据服务与降级

继续使用统一注册表、`fetchEndpoint`、原始响应留档、mapper 和证据信封，不另建页面直连数据源。

| 能力 | 来源策略 | 失败后行为 |
|---|---|---|
| 指数趋势 | 当前 TDX `/` 健康检查 → `/index/day` → 已有备源 | 只降级指数模块，保留缺口 |
| 个股报价 | 当前腾讯完整行情 → 缺失行由 TDX `/quote` 补位 | 保留实际来源；没有真实报价时间不能用于严格盘中确认 |
| 个股日线 | 当前 TDX `/kline/day/qfq` → 腾讯/东财 | 不拼接不同复权锚点；按业务日截断 |
| 涨停及题材 | 现有东财池与同花顺/问财归因 | 不用 TDX 当前报价重建历史涨停池 |
| 成分关系 | 现有可信关系来源；后续评估 TDX 板块、mx-data | 无完整关系则停留事件样本范围 |
| 事件与风险 | 已有公告源，mx-search 补充检索 | 资讯不可用不阻断数值计算，关联核验仍标缺口 |

TDX README 还列有 `/code/stocks`、`/block/data`、`/tdx/bk`、`/minute`、`/kline/minute` 等能力。它们存在于服务文档，不代表 Vibe AStock 已适配或业务验收。接入前验证真实响应结构、时间单位、证券范围、分页、板块成员新旧程度和访问成本；盘中历史量能还需核验数据可得性。

mx-data、mx-search 当前是已安装脚本，不是自动数据路线。新增受控适配器须登记 `auth_env: MX_APIKEY` 等所需凭据声明，遵守现有凭据转交机制；缺密钥显示未配置。只向外发送公开证券/方向与查询问题，日志和结果不保存认证信息。

mx-search 的结果按公告、政策原文、媒体报道、研报观点分类，记录标题、链接、发布时间、抓取时间。查询“截至某时刻”不构成时间校验：仍需验证结果发布时间及实际可得时间。搜索摘要没有原文支持时不能确认公司业务、政策影响或数值字段。

## 8. 计算、存储与接口草案

### 8.1 分层

```text
已有注册端点 + 新增受控数据适配器
                  ↓
业务日/观察时点校验、单位标准化、完整性检查
                  ↓
全量方向关系 + 固定样本行情 + 原始引用
                  ↓
确定性指标与规则 → 版本化观察结果
                  ↓
页面/导出；按需 AI 解读（只读公开证据包）
```

建议新增代码位于 `orchestrator/src/finance/mainline/` 与 `desktop/src/verticals/finance/mainline/`；源适配器放现有 data-access sources，确有复用价值的确定性计算再扩展 `calc/` 契约。行业逻辑不进入 finance 之外的 Core。

AI 只解释程序结果和证据，不负责算数、修改标签、发明关联或决定观察名单。即使没有接 AI，功能应能完整生成事实表。AI 输出沿用现有数字与引用核对，失败不影响确定性页面。

### 8.2 拟议接口（尚未注册）

| 接口 | 用途 |
|---|---|
| `GET /api/finance/mainline?date=YYYY-MM-DD&mode=close` | 读取/生成所选收盘观察 |
| `GET /api/finance/mainline?mode=intraday` | 读取今天最新可用观察 |
| `GET /api/finance/mainline/:snapshotId` | 读取不可变历史版本 |
| `POST /api/finance/mainline/refresh` | 显式刷新，返回任务 ID，复用现有任务进度机制 |

实际路由命名在实现时与现有 HTTP 服务约定统一。刷新、取消与历史读取需有明确服务契约；刷新不覆盖已有成功版本。

结果顶层至少保存：`schema_version`、`algorithm_version`、`config_hash`、`snapshot_id`、`mode`、`trade_date`、`as_of`、`generated_at`、`status`、`universe`、`coverage`、`market_context`、`directions`、`observations`、`gaps`、`source_attempts`。

每项指标保存 `value / unit / denominator / effective_at / fetched_at / source / evidence_ids / raw_ref`；每条规则保存条件、实际值、三态结果和未通过原因。`null` 必须有原因码，例如 `missing_source`、`stale_quote`、`unknown_membership`、`incomplete_universe`、`not_comparable`。

新增产物只放 `.local/mainline/<业务日>/<快照ID>/`，包括请求摘要、输入证据包、关系版本、参数、计算结果、可选 AI 解释。引用不能指向易淘汰的临时缓存；落盘时复制本次所需原文或使用有保留保证的归档引用。

### 8.3 时间与历史回放

业务发生时间、信息首次可得时间、抓取时间分开。历史回放只能使用截止时刻已知的信息；今天取得的历史业务数据只能支持“事后重算”，不能冒充当时实时识别能力。事后新增的题材标签、成员、公告修订不得进入过去快照。

盘中回放依赖从功能启用后积累的分钟/观察快照。没有历史快照时，只承诺收盘事后重算，并在界面写明。旧版结论保留，修订作为新版本保存。

## 9. 性能与更新策略

- 先返回最近有效观察及其真实时间，再加载变化模块；无旧结果时显示各模块进度。
- 每个时间窗聚合一次共享输入，方向卡和个股表共用行情批次，不为每个方向重复拉全市场。
- 个股报价仍遵守 `tx_quotes_batch` 注册参数上限（现有候选池每批 50 只）；底层 TDX 批次大小不等于公开端点参数上限。
- 成员关系按业务变化慢更新，行情快更新；同请求合并、全局限流、健康负缓存继续复用。
- 已归档的前几日输入不随每次页面刷新重取；结果缓存键包含模式、业务日、样本、参数、算法和成员版本。
- 盘中新增聚合快照初始建议 30 秒刷新、最大跨源时差 30 秒、严格行情最大陈旧 60 秒；这些属于新模块的拟议策略，不能放宽原端点要求。60 秒原始池缓存若让底层数据过期，显示真实年龄并拒绝确认，不能仅更新页面时间。
- 午休与收盘停止盘中轮询，保留原时点；集合竞价不套用连续交易规则。源没有可靠行情时间时使用“时间未核实”状态。
- 新闻与关系补全走低频独立任务，不阻塞行情主流程；共享上游失效时避免每个方向逐一重复探测。

性能验收目标：缓存首屏 P95≤2 秒；已有历史缓存的增量观察 P95≤15 秒；全量冷启动拆为可取消任务，45 秒内返回已有模块与缺口，不等待最慢源统一结束。这些是待测目标，现有端点可能有更长超时；实现任务预算需要从聚合层取消传递到各取数子进程，不能仅靠 HTTP 读取超时。

不在每次刷新中全量拉取全市场 800 根前复权日线。先定方向范围，再补观察所需历史；全成分模式分批更新并记录覆盖进度。

## 10. 验证方法与验收条件

### 10.1 必需用例

| 场景 | 预期结果 |
|---|---|
| 高度上升但涨停广度/晋级率下降 | 保留分化描述，不由高度单项决定主线 |
| 单只个股连续涨停，其余没有扩散 | 不满足多成员主线条件 |
| 新方向当日多只首板，无历史延续 | 单日活跃或扩散观察，不显示持续主线 |
| 没有任何方向满足条件 | 空候选 + 已核对范围与原因 |
| 同一股票多个标签/多个源重复出现 | 同方向去重，多方向独立归属 |
| 展示名单截断 | 不能用于全量广度或成分分母 |
| 某日无题材原因、部分成员缺行情 | 缺数据/样本下限，不补零，不判断消失 |
| TDX 健康成功、报价路由失败 | 逐能力回退并保留错误，不整站判成功 |
| TDX 有价格但无真实报价时间 | 可展示来源事实，严格盘中条件缺数据 |
| 不同源池时间差超限、缓存重放 | 不确认跨池规则，不算第二次独立确认 |
| 盘前/午休/节假日/收盘集合竞价 | 正确时段状态，不生成虚假即时信号 |
| 历史输入混入次日公告或今日关系 | 时点校验拒绝，不用于历史能力评价 |
| 妙想无密钥/限流/非结构化摘要 | 明确缺口，其他模块继续 |
| 新快照失败、重复刷新或取消 | 保留旧成功版本、合并请求、可取消 |
| AI 引用不存在或改写数字 | 校验失败，确定性结果仍可查看 |

### 10.2 质量评价

先衡量数据质量：关系覆盖率、有效报价率、时间可核验率、跨源时差、无结果比例、错误率、响应 P50/P95、单次请求量。再衡量标签稳定性、状态变化原因可解释性，以及固定观察队列在后续快照中的事实变化。

后续表现采用预先登记的窗口（如下一交易日、3 日、5 日）做历史统计，同时保存被排除和缺数据样本，避免只统计后来上涨者。使用时点成员及退市证券，避免幸存者偏差；采用按时间分割的校准/留出窗口，参数冻结后再评价。不把研究样本收益当作可成交策略收益；若做策略回测，另行定义 T+1、交易费用、涨跌停成交约束等假设。

验收完成必须包括：固定输入确定性重算一致、原始引用可追溯、无未来信息、缺值三态正确、源降级正确、页面可取消、真实本机页面联调通过。模拟数据、接口探测与真实业务验收分别报告。

### 13.2 现有实现可以复用到什么程度

**盘中：调度、原始输入和计算各自区分。** `shortline/intraday.ts` 的六时点为 09:25、09:35、10:00、11:30、14:00、15:00。其 `Snapshot` 保存队列汇总及 live 读数，没有完整方向成员报价序列。六时点也不能满足“两次间隔 5 分钟”的持续确认。新增模块需保存自己的方向级输入，复用交易日门禁与调度底座；上午/下午确认不得跨午休接续，09:25 竞价快照不能当连续竞价确认。

**运行方式：明确是否在页面关闭后继续。** 原实时动态页面关闭就不再驱动报价；六时点任务则依赖本机服务持续运行。首版主线盘中自动更新建议页面驱动，页面关闭不承诺连续确认和完整回放；收盘快照复用后台任务。后续若提供后台持续观察，应单独启用、有范围与请求预算，不能暗中扩大现有轮询负担。服务休眠、离线后恢复标记观察中断，不补造错过的快照。

**验证：沿用纪律，保持数据契约。** `verification.ts` 当前只收市场层面读数，`verify_metrics.ts` 是固定清单。不要把方向或个股验证写进原 `verification` 记录再混算历史战绩。方向观察另存验证记录，引用原快照，保留下一交易日 09:15 后新增/修改标为事后的纪律；原市场验证继续按原规则运行。

**候选池：增加范围适配器。** 现有 `candidatePool` 不支持任意题材范围，也不支持趋势/相对强弱条件。新增范围用服务端签发的 `snapshot_id + direction_id + membership_version` 解析；不信任浏览器传入成员名单、任意文件路径或截断展示表。候选池的表格和基础指标可复用，新条件需要单独定义字段、单位、时间与三态测试。条件模板和范围写入 URL 或受控预填，不能只依靠临时页面状态。

**通知：稳定变化才发。** 只在确认后的状态变化发送摘要，缓存命中与重复查看不再次通知。拟议去重键包含业务日、方向、变化类型、确认事件 ID；指标轻微波动不重新发。数据不足发数据状态提示，不能写成“方向转弱”。同一次确认事件重启后仍不重复发送，消息链接指向对应不可变快照。

### 13.3 主线不能只靠涨停样本

原方案 A+B 能较快得到“事件题材活跃观察”，但大型行业趋势可能不依赖多股涨停，必须与短线题材分开。

因此区分两个发现通道：

- **事件题材通道**：涨停原因、首板、昨日队列反馈，按第 5.3 节判断，范围和标签明确标为事件样本。
- **行业趋势通道**：完整成分涨跌宽度、中位数相对强弱与成交结构，按第 5.4 节判断；依赖 D 阶段关系及行情覆盖。

首版页头显示启用的通道和覆盖范围。行业趋势通道未就绪时明确“行业趋势识别未启用”，不能把题材结果改名为全市场主线。资金流榜仅提供辅助事实，不替代趋势通道。

关联观察股同时区分“已活跃样本”和“成分拓展样本”。后者需要完整成分与经营关联证据，不以“涨幅低”“没涨停”直接命名为补涨潜力，也不让模型根据名称猜测成员。

### 13.4 数据完整性和时间精度再约束

1. **每个输出独立判断可用性。** 记录源是否完整、关系是否完整、分母是否已知；全市场缺一只归因不能抹掉其他方向事实，方向内缺报价也不能把它从固定队列删除后重算出更好的表现。
2. **区分抓取时间与市场时间。** 源只提供抓取时间时，标记 `time_basis=fetched_only`，不能承诺 30 秒市场同步。严格盘中规则需要真实市场时间；不满足时只展示标明抓取时间的样本事实。
3. **30 秒跨源时差是目标，不是现有能力。** 原池缓存 60 秒、多次串行限流会使池间不同时。不要全局关闭缓存来硬追同步；仅对必要输入做有限刷新，仍超限就停算对应比率。静态日线/成员版本不与盘中行情共用同一陈旧阈值。
4. **独立更新有可核验标识。** 保存底层请求 ID、内容摘要、数据时间区间和缓存年龄。内容相同不必然是缓存：来源证明是新的市场观察才计入二次确认；只有新生成时间或新顶层快照 ID 不够。
5. **历史关系不能由今推昔。** 今日下载的历史业务表和当前概念成员仅能事后分析；真正历史检验需保存当时可得关系，缺少时从功能启用日起累积。

### 13.5 阈值、证据与统计改进

初始 L≥3、C≥30% 等只是一个可复算基线，不能宣称适合所有题材规模和市场环境。输出绝对数量的同时显示目标市场占比、实际样本数和可比历史分位；分位缺样本就不显示。首版不为提高命中率自动调参，后续使用预先划定的时间窗口比较固定参数版本。

将“活跃程度”“持续/扩散”“分歧事实”“数据可信程度”四组信息分开。数据覆盖高不等于方向强，方向强不等于收益概率高。新闻、资金流、经营关联可成为支持或反证，但同源转载或同一原始表的多个衍生指标不能被算成多个独立来源。

复盘 AI 的数字核对只解决数字与引用一致性，不能证明主线规则有效。规则评价另看时间留出样本、结果稳定性和误识别案例，并保留“无主线”和“证据不足”的天数。

### 13.6 调整后的实施优先级与验收

| 优先级 | 实施任务 | 必须通过的验收 |
|---|---|---|
| P0 | 全量事件关系输出、时间/覆盖契约、快照版本；源响应抽样 | 不用展示截断重建全量；缺失只影响相关指标；配置和私密信息不外发 |
| P1 | 每日复盘嵌入事件题材观察、候选池范围拓展、研究跳转 | 同一快照在复盘和候选池成员一致；不新增重复轮询；不自动启动 AI 研究 |
| P2 | 页面驱动盘中观察、方向成员快照、稳定变化通知 | 午休/离线重建确认；缓存不计重复确认；页面关闭行为明确；通知重启去重 |
| P3 | 全成分行业趋势、妙想关系/资讯适配 | 行业趋势与事件题材独立；真实源字段/日期/单位和完整性验收 |
| P4 | 独立方向验证记录、历史评价、可选解释 | 不污染原明日验证；当时可得数据回放；未来信息拒绝；原研究归档正常 |

在原第 10 节测试之外，增加如下回归：现有候选池自选/指数查询不变；持仓范围隐私仍成立；原六时点快照和明日验证不受影响；产业研究静态 hot 不影响动态标签；GPU 租金故障不阻断无关方向；事件日历 30 只截断不伪装为观察股全覆盖；方向页面取消不取消其他页面共享请求的有效订阅。

最终交付分清三类状态：已有代码可复用、需要适配、已在真实业务中验收。本轮只完成第一类核查与第二类设计，不把代码存在或菜单可见当作已验证业务链路。
