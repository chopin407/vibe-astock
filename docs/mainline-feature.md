# 主线方向与关联观察股

2026-11-06：已实现事件题材与 TDX 行业观察、妙想补充、严格盘中确认和方向独立验证。它整理已发生的事实，保留关联个股供条件核对，不估算未来收益概率。下方“后续补齐验收”是最新交付范围；首版验收数据保留用于追溯。

## 使用

1. 更新代码后重新启动本机服务（按原方式 `scripts\start.cmd`）。已运行的后端需要重启才能登记新视图；不要同时启动多个实例抢占原端口。
2. 打开“每日复盘”，在“主线方向与关联观察股”点击“生成新观察”。日期随每日复盘的业务日，收盘与盘中模式由页面上下文确定。
3. 在盯盘页也可生成今天的盘中观察，勾选“每分钟更新”后仅在页面开启且可见时轮询。连续竞价之外服务拒绝生成盘中数据，不补造停机、午休或错过的观察。
4. 使用搜索查找题材，按需加载更多方向，展开查看完整关联成员。卡片按当日已归因涨停数排列；这不是综合潜力排名。一股多题材不能相加为市场总数。
5. 点击“进入候选池核对本快照成员”，设置成交额、换手或其他条件，再点击“开始核对”。范围固定为该观察版本，不受此前保存的自选/持仓偏好影响。
6. 点击个股进入“个股深挖”或“多空核验”，仅切换研究对象，不自动启动模型研究。使用历史版本下拉回看旧观察；“导出证据”保存本机 JSON。
7. 展开“行业趋势与完整成分”，先“扫描行业指数”，再选择行业并点击“核对行业完整成分”。目录加载只取分类；指数扫描只给初筛，完整成分行情需要另行核对。行业快照也可进入候选池，按相对上证指数涨幅筛选。
8. 在方向卡的“补充关系、事件与下日验证”中查询妙想、读取补充存档，或记录下一交易日是否活跃/持续的预期。底部“方向独立验证”读取独立结果；不会改原“明日验证”的记录或战绩。

没有存档时不自动触发三个交易日的网络请求。生成期间可取消；失败时保留之前显示的成功版本。重读存档不会刷新行情。旧版本显示原采集时间，不代表当前状态。

## 已实现

| 功能 | 行为 |
|---|---|
| 完整输入 | 直接读取涨停池与涨停原因关系，不使用题材树前几只展示名单 |
| 市场背景 | 嵌入每日复盘，与既有市场状态及情绪读数同屏；不再复制一套环境评分 |
| 多维度状态 | 当日活跃、样本持续活跃、首板扩散、分歧、昨日活跃今日未延续独立计算 |
| 缺失处理 | 每日归因覆盖、每维度满足/不满足/缺数据；缺失不记为零 |
| 关联队列 | 同方向去重，保留昨日未延续成员；每只成员标原始数据日 |
| 候选核对 | 当前快照的成交额、换手和名称条件；估值/市值/停牌状态不足时标缺数据 |
| 历史安全 | 历史候选不取当前报价补空；快照包含输入、计算结果、证据和原文引用 |
| 更新 | 手动生成，盘中可选每分钟更新；45 秒取数预算、共享取数层取消信号 |
| 归档 | `GET /view/mainline` 只读；`POST /view/mainline` 生成不可变版本 |
| 收盘任务 | 15:45 保存事件方向观察和收件箱摘要；按交易日门禁，摘要按业务日去重 |
| 行业通道 | TDX 分类表全成员、行业指数扫描、所选行业成员上涨占比/中位涨幅/相对基准，保留缺失成员 |
| 妙想补充 | 关系查询、最多三只方向内公开个股的指标补充、事件检索及独立存档；不把摘要和未核实表格直接用于计算 |
| 盘中确认 | 真实报价新鲜度、覆盖率、跨源时差、同成员、时间推进与两次5–10分钟确认；重放和午休跨段拒绝 |
| 方向验证 | 独立、不可覆盖的预期记录；下一个交易日收盘快照核对，09:15之后形成的基准/预期标事后 |

初始规则见[设计第 5 节](mainline-discovery-design.md#5-主线识别规则-v1)。完整市场比较所需关系不足时，只声明已覆盖样本表现。例如其他股票缺少题材原因，不影响某已知队列的正向持续证据；它会阻止“全市场领先”“完全消失”等需要完整分母的结论。三个交易日不完整但当日有效时仍能展示当日观察。

## 明确的可用范围

- 行业通道的“完整”指 TDX 本次返回分类表的完整成员；源没有提供分类更新日，不能据此证明是交易所最新成分。分类版本、下载时间随快照保留，不用于回填历史行业归属。行业持续性采用最近三个完成交易日的行业指数相对表现，不冒充逐日全成分中位数趋势。
- 题材名称来自源站归因；不同标签暂不自动合并，来源归因不等于公司确认。
- 盘中确认需要真实交易所报价时间，覆盖≥90%、时间差≤30秒、当前最旧有效报价≤60秒，且两次同范围持续条件满足、市场时间推进并相隔5–10分钟。行业通道要求分类版本一致；事件通道要求对应方向成员一致且涨停样本得到报价核验。TDX 兜底价格没有真实报价时间时不确认。当前已实现页面确认结果，未增加盘中向外部群机器人主动推送。
- 行业成分拓展可以展示尚未涨停的关联股，是否有研究价值由条件核对决定。“没涨停”“涨幅低”不会自动变成潜力结论。妙想关系表为空时，只补最多三只已有方向成员的公开指标；这不证明新增成员关系。
- 妙想结果由用户点击后经注册表取数，要求服务进程可读取 `MX_APIKEY`。凭据从环境继承，不写入页面、仓库或产物；未配置时显示失败。没有使用私人台账内容构造查询。检索文章需要有效 HTTP(S) 链接和截止日之前的发布时间，仍需人工核验原文。
- 原“明日验证”的市场指标与战绩不变；主线观察不写入其固定指标集合。
- 盘中今天开市校验、未来日拒绝、历史盘中只读依赖现有交易日历；源无数据或空池尚不能证明有效零值时按不可用处理。
- 不发送持仓、成交、成本、盈亏给模型或数据服务；本功能不读取私人台账，不自动调用用户配置的研究模型。妙想自然语言查询仅发送公开方向、业务日及最多三只公开成员代码。所有运行产物保存于本机 `.local/`。

## 服务与文件

实际注册视图为 `mainline`，不是设计草案中的 `/api/finance/mainline`。

| 请求 | 参数 | 结果 |
|---|---|---|
| `GET /view/mainline` | 可选 date、mode、snapshot_id | 选定/最新观察及最近 50 个匹配日期版本；无存档为 null |
| `POST /view/mainline` | JSON：date（可选）、mode（close/intraday）、refresh（可选） | 新快照；失败不替换旧快照 |
| `GET /view/candidates` | universe=direction、snapshot_id、direction_id 及现有条件 | 固定版本成员条件核对 |
| `GET /view/mainline_industries` | scan=1 可选 | 当前行业目录及可选的行业指数扫描 |
| `POST /view/mainline` | 额外 industry_id | 当前业务日、所选行业完整成分观察；不接受历史成分回填 |
| `POST /view/mainline_supplement` | snapshot_id、direction_id | 妙想数据与资讯补充；独立保存 |
| `GET /view/mainline_supplement` | snapshot_id | 补充存档 |
| `POST /view/mainline_verification` | snapshot_id、direction_id、metric（active/persistent）、expected（布尔） | 不可覆盖的方向预期记录 |
| `GET /view/mainline_verification` | 无 | 下个交易日收盘核对、缺失和事后状态 |

沿用原本机 API 鉴权与 JSON POST 防护；浏览器通过现有代理调用，不在页面填写任何数据源令牌。

新增注册端点 `cn_mainline` 经 Python `sources/mainline.py` 生成信封。每次取数使用独立 `mcp/mainline-<随机编号>/` 会话，保留原文与计算信封；观察版本保存在数据根目录 `mainline/<时间戳>-<随机编号>.json`。读取路径经过既有 `safePath` 检查；不接受浏览器传入任意文件路径或成员名单。

## 验收记录

2026-11-06 完成以下验证（未进行浏览器点击式联调，不是正式发版审计）：

- 数据源回归：824 项通过；含新算法的完整成员、缺失、昨日队列、状态共存、历史和日期边界测试。
- 受影响 Node 回归：42 项通过，覆盖主线归档、候选池、调度、盘中快照。
- 前端定向测试：8 项通过，含实际组件渲染、完整成员显示与固定快照候选入口。TypeScript 与前端构建另行检查。
- 真实取数及临时本机 HTTP 服务验收：POST 生成 → GET 指定版本 → 候选池固定成员核对成功，验收服务随后关闭。11 月 6 日取得 449 个三日窗口标签记录，其中 3 个满足已覆盖样本持续规则，664 条证据；实际页面只分页展示今日或昨日有样本的标签。
- 归因覆盖：11 月 4 日 116/118、11 月 5 日 83/84、11 月 6 日 32/32。返回 partial，保留 2 项历史覆盖缺口。数量是本次抓取观察，不承诺源站修订后不变；后续刷新另存版本。
- 实际候选 HTTP 验收选择一个方向的 5 个成员，成交额下限与名称排除条件核对成功；仅证明调用链与样本一致，不代表选股效果或完整策略验证。

本机基线：前端原 406 项中 403 项通过、3 项失败；Python 基线在沙箱下 1669 项通过、40 项失败，包含文件权限和 SSL 环境问题。普通权限、仅清除测试子进程 SSLKEYLOGFILE 后数据源 824 项通过。全量 Node 基线遇到平台文件权限与挂起，已终止该测试进程；不宣称全仓测试全绿。

## 后续补齐验收

- 新增注册端点 `cn_industry_catalog`、`cn_industry_observation`、`mx_direction_data`、`mx_direction_news`，总计188个端点。目录和端点模块契约检查通过。
- 行业真实取数：56 个 TDX 行业分类及对应指数可扫描；煤炭分类32只成员取得32/32有效同日行情。该次成分涨幅中位数 -1.04%、上涨占比15.625%，相对基准条件与持续条件按规则独立核对。这是验收快照，不是当前市场结论。
- 真实临时 HTTP 链路：行业目录扫描 → 行业快照 → 32只成员候选池 → 相对涨幅核对（17只满足、15只不满足）→ 妙想补充 → 独立方向预期 → 存档读取，均成功；验收服务已关闭。
- 妙想返回8条具备可用链接/日期的文章。行业成员关系查询未返回结构表；按已公开方向成员补取指标得到2个结构表，明确保留日期/单位核验边界，不将其当作新增关系或完整成分依据。
- 相关后端回归44项、前端定向渲染/调用测试9项通过，后端类型检查与前端构建通过。数据源全量测试836项通过，mypy检查121个源文件通过；188个端点的静态契约检查无问题。
- 验证记录与原市场“明日验证”完全分离：测试涵盖时间推进、缓存重放、午休跨段、成员版本变化、陈旧行情、事后记录、隔日缺口和目标缺失。盘中双时点确认目前完成模拟时钟测试，收盘后的本轮没有声称完成真实交易时段的双时点现场验收。

日线技术条件的更多模板、同时间成交额比较、可成交策略回测和收益统计仍是扩展研究任务，未以本功能的条件核对替代。总体方法和约束见[设计文档](mainline-discovery-design.md)。
